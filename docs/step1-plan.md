- 대기(앱 아닐 때): `아이콘으로 연 뒤에 할 수 있어요.`
- 진행: `내보냈어요. '가져오기'에서 그 파일을 고르면 확인이 끝나요.`

- 상태가 안 바뀌고 회색 안내만 뜨는 경우
  - AbortError: `공유 창이 닫혔어요. 다시 누르면 돼요.` ([사실] 이 이름은 파일 읽기 실패에도 쓰여서 '취소'로 단정하지 않아요)
  - NotAllowedError(아이폰) 첫 번째: `한 번 더 눌러 주세요.` 이번 실행에서 두 번째면 위 실패 문구로 올려요.

  - **이미 통과한 뒤:** 결과가 무엇이든 상태를 내리지 않고 회색 안내만 띄워요.

**7 `import` 백업 파일 가져오기**
- 대기: `메뉴가 뜨면 '파일 선택'을 누르고, 방금 저장한 파일을 골라 주세요. 지금 있는 내용은 바뀌지 않아요. 선택창이 안 닫히거나 안 뜨면 앱을 닫았다 다시 열어 주세요.`
- 대기(앱 아닐 때): `아이콘으로 연 뒤에 할 수 있어요.`
- 통과: `imjang-test-2026-11-05.json을 14:32:07에 읽어 확인했어요. 글자까지 모두 같아요.` 파일 이름은 표시만 하고 판정에 쓰지 않아요. 고를 때마다 글자가 바뀌어요.
- 진행(`not-this-run`, probe가 없거나 nonce가 다름): `올바른 백업 파일이지만 이번에 내보낸 파일이 아니에요. 방금 저장한 파일을 골라 주세요.`
- 실패 (끝에 공통으로 `지금 있는 내용은 그대로예요.`)
  - `read-failed`: `파일을 읽지 못했어요. (오류 이름)`
  - `empty`: `빈 파일이에요.`
  - `too-big`: `파일이 너무 커요. 내보낸 백업 파일을 골랐는지 봐 주세요.`
  - `encoding`: `글자 형식이 달라요. 사진이 아니라 내보낸 백업 파일을 골랐는지 봐 주세요.`
  - `bad-json`: `파일이 잘렸거나 손상됐어요. 사진이 아니라 내보낸 백업 파일을 골랐는지 봐 주세요.`
  - `other-app`: `임장노트 백업 파일이 아니에요.`
  - `newer`: `더 새 버전 앱에서 만든 파일이에요. 위쪽 '다시 불러오기'를 누른 뒤 다시 해 주세요.`
  - `probe-diff`: `파일 내용이 내보낼 때와 달라요. 옮기는 중에 바뀐 것 같아요. 캡처를 Claude에게 보내 주세요.`
- 이미 통과한 뒤의 실패는 빨간 실패로 내리지 않고 회색 안내(파일 이름·시각·이유)로 보여 줘요.

**내보내기·가져오기가 같이 통과하는 이유.** [사실] 공유 성공은 파일이 보관됐다는 뜻이 아니에요(3-3). 그래서 공유 완료는 `진행`이고, 가져오기 일치에서 두 행이 함께 통과해요.

**버튼**

| id | 글자 | 언제 |
| --- | --- | --- |
| `#topReload` | 다시 불러오기 | 항상 |
| `#saveBtn` | 저장 시험하기 | persist 대기 카드 주요 |
| `#exportBtn` | 백업 파일 내보내기 | export 주요, import·완료 카드에서 작게 |
| `#importLabel` + `#importFile` | 백업 파일 가져오기 | import 주요, export·완료 카드에서 작게 |
| `#downloadBtn` | 파일로 바로 저장 | export·import·완료 카드에서 작게 |

앱으로 안 열렸을 때는 `#topReload`와 지도 위 조작만 있어요. persist 진행 카드에는 주요 버튼이 없어요. 다음 동작이 앱 밖에서 일어나기 때문이에요.

**재시작을 넘나드는 흐름**
- 저장 대상
  - search·gps는 **ok·fail만** 저장해요. half를 복원하면 요청도 없이 '찾는 중'에 갇혀요.
  - export는 half·ok와 경로(`share`/`download`)를 저장해요.
  - import는 ok와 문구를 저장해요.
  - persist는 시험 기록에서 계산해요. standalone·map은 매번 다시 판정해요.
- **앱으로 열렸을 때만 읽고 써요.** 예외는 앱 밖의 진단 줄 '시험 기록 있음/없음' 읽기 하나이고, 판정과 복원에 쓰지 않아요.
- **버전이 다르면 기록 전체를 무시해요.**
- 저장소가 고장 나도 그 회차는 메모리로 동작하되, 저장 행은 실패로 표시해요. 지도와 백업은 계속 작동해요.
- 파일 선택창이나 공유 창이 페이지를 다시 읽게 하는지 [모름]이라 단계마다 바로 저장해요.

**다시 불러오기와 시작 감시** (모듈이 아닌 인라인 일반 script)

[사실] 모듈 하나만 실패해도 `app.js` 전체가 실행되지 않아요. 그래서 버튼을 `app.js`에서 연결하면 정작 필요할 때 죽어 있어요.

```js
async function reloadApp() {
  showBusy('불러오는 중…');
  let ok = false;
  try {
    const c = new AbortController();
    const t = setTimeout(() => c.abort(), 8000);       // 8초는 설계값
    const r = await fetch(location.pathname, { cache: 'reload', signal: c.signal });
    clearTimeout(t);
    ok = r.ok;
  } catch {}
  if (!ok) { showNearButton('인터넷이 안 잡혀요. 연결된 뒤 다시 눌러 주세요.'); return; }
  window.__beforeReload?.();   // app.js가 살아 있으면 markExpectReload
  location.reload();
}
```
- 표시는 응답을 받은 뒤에 남겨요. 실패했다가 나중에 다시 열 때 잘못 세지 않게 하려는 거예요.
- 시작 감시: `app.js`가 `window.__appStarted`를 남기지 않으면 8초 뒤 `#ver`를 meta 값으로 채우고 `앱을 불러오지 못했어요. 인터넷을 확인하고 위쪽 '다시 불러오기'를 눌러 주세요.`를 보여 줘요. 늦게 시작되면 숨겨요.
- [모름] 응답 확인과 reload 사이에 신호가 끊기면 오류 화면이 남을 수 있어요. 코드로 없앨 수 없는 작은 구멍이에요.
- 당겨서 새로고침은 직접 만들지 않아요.

**진단 줄** (폰 측정값을 받는 유일한 통로)

`place · navigator.standalone · display-mode · innerWidth×innerHeight · screen.height · 안전영역 위/아래 · 문서 scrollHeight · nav type · 다시 열기로 센 로드의 nav type · persisted · 내보내기 경로 · 시험 기록 있음/없음`

앱 밖에서는 원본 UA를 덧붙여요(카톡 판별을 실제 값으로 확인하려는 것). 앱 안에서는 파싱한 iOS 버전을 표시하지 않아요. 버전은 사용자가 설정에서 읽어요.

**같은 행에 속해서 함께 고치는 것:** 그림 시간 초과에도 `showMapMessage`를 띄우고, 늦게 뜨면 숨겨요. 카드 규칙이 지도 실패를 건너뛰므로 이것이 없으면 실패가 눈에 안 띄어요. Map 예외와 로딩 중 검색 잠금은 백로그예요.

## B. 저장 모듈 `js/lib/store.js`

```js
export const SCHEMA_VERSION = 1;
export const KEY_PREFIX = 'imjang-map:';
export function createStore(getStorage) // 예: () => window.localStorage
store.read(name)  → { ok:true, data } (없으면 data:null) | { ok:false, reason:'unavailable'|'corrupt'|'newer', detail }
store.write(name, data) → { ok:true } | { ok:false, reason:'quota'|'unavailable'|'verify-failed'|'unknown', detail }
```

- `getStorage`를 함수로 받아요. 접근 자체가 던지거나 null이어도 try 안에서 처리되고, 브라우저 없이 가짜 Storage로 시험돼요.
- 값은 `{"schemaVersion":1,"data":…}`로 감싸요.
- `write`는 쓴 뒤 다시 읽어 일치해야 ok예요. 판별은 `e.name === 'QuotaExceededError'`.
- 메모리 대체 없음, `clear()` 없음, 맨 위에서 localStorage 접근 없음.
- `corrupt`면 원래 값을 지우지 않아요.

**1단계 저장 내용** (키 `imjang-map:check` 하나)
```json
{ "version":"0.1.2-…",
  "test":{"code":"4821","savedAt":"ISO","expectReload":false,"reopenSeen":false,"reopenNav":null},
  "results":{"search":{"state":"ok","msg":"…"},"export":{"state":"half","via":"share"}},
  "backup":{"nonce":"…"} }
```

**판정** (`js/lib/checks.js`의 순수 함수, 시작할 때 실행)
- 시험 값이 있고 `expectReload`가 있으면 표시를 지우고 '다시 불러옴' 문구를 보여 줘요. 통과에는 세지 않아요.
- 시험 값이 있고 표시가 없으면 `reopenSeen=true`, `reopenNav`에 nav type을 기록해요.
- `reopenSeen`이 true면 통과예요. 이 판정의 한계는 K에 있어요.

**`persist()`:** 저장 시험 클릭 안에서 존재를 확인한 뒤 호출하고, 결과는 기다리지 않아요. `persisted()` 값은 진단 줄에만 써요.

**안 만드는 것:** `store.remove`, 매물 구조, 사용량 70% 안내, 형식 변환, write의 newer 보호(2단계).

## C. 백업 `js/lib/backup.js`

**시험 파일 형식**
```json
{ "app":"imjang-map", "schemaVersion":1, "purpose":"connection-test", "exportedAt":"…Z",
  "probe":{ "nonce":"…", "text":"약국 임장 ☕🏥 \"따옴표\"\n줄바꿈" } }
```
- `JSON.stringify(x, null, 2)`, BOM 없음.
- 파일 이름은 `imjang-test-YYYY-MM-DD.json`이고, 폰의 날짜로 만들어요(toISOString은 아침 9시 전에 전날이 돼요).
- 확장자는 상수 `BACKUP_EXT` 하나예요.
- 진짜 백업과 다른 파일이에요. 2단계의 복원은 `purpose`가 있으면 거절한다고 지금 기록해요. 2단계 형식 제안은 `{app, schemaVersion, exportedAt, count, listings}`예요.

**내보내기 경로** (`chooseExportPath`)

| 환경 | 기본 | 보조·실패 |
| --- | --- | --- |
| 아이폰·아이패드 앱, canShare 가능 | `navigator.share({ files:[file] })`만. title·text 없음 | 자동 전환 없음. 작은 버튼 '파일로 바로 저장' |
| 그 외 전부, 또는 canShare 없음·false | `a[download]` | - |

- 안드로이드는 [사실] 허용 목록에 json이 없고 canShare가 true를 거짓으로 줘서 share를 시도하지 않아요. `.txt` 경로는 4단계나 K의 조건에서 다시 봐요.
- 클릭 핸들러 안에서 await 없이 File까지 동기로 만들고 바로 share를 불러요.
- `a[download]`의 Blob은 `application/octet-stream`, URL 폐기는 60초 뒤예요.
- 버튼을 share 결과에 묶어 잠그지 않아요.
- nonce는 회차당 하나로 고정하고 share 전에 저장해요.

**가져오기 검사** (`parseBackup`, change 핸들러 전체를 try/catch로 감쌈)
1. 크기: 0바이트, 또는 1MB 초과면 거부. 1MB는 설계값이에요(시험 파일은 1KB 미만). accept가 없어 동영상을 고를 수 있으니 통째로 읽기 전에 막아요.
2. 읽기: `file.arrayBuffer()` 실패면 `read-failed`
3. `TextDecoder('utf-8',{fatal:true})`
4. `JSON.parse`
5. 최상위가 객체가 아니거나 app이 다르면 `other-app`
6. schemaVersion이 정수이고 1 이상인지(아니면 `other-app`), 앱보다 높으면 `newer`
7. probe가 없으면 `not-this-run`, nonce가 다르면 `not-this-run`, text가 다르면 `probe-diff`

`file.type`·`file.name`은 판정에 쓰지 않아요. `accept`는 넣지 않아요. 고른 뒤 `input.value=''`로 비워요. 선택 취소는 이벤트에 기대지 않아요.

**비파괴:** 1단계 가져오기는 읽고 비교만 해요. `__proto__` 방지 복사와 count 일치는 복원이 생기는 2단계로 넘겨요.

**백업 알림과 기타 항목은 2단계로** (J7에서 묻고 기록해요)
- 1단계에는 지킬 데이터가 없고, 알림 기준인 '마지막 변경'은 매물 저장이 있어야 의미가 있어요.
- '내보내기를 마친 때'라는 정의만 `docs/dev-notes.md`에 적어요. 시각 저장은 2단계에서 버전과 무관한 별도 키로 해요.
- [추론] 알림은 앱을 열어야 뜨므로 안 쓰다 사라지는 경우에는 도움이 안 돼요.
- 2단계 완료 기준(`docs/dev-notes.md` 99줄): 백업 알림, 빈 화면의 가져오기 버튼, 실데이터 내보내기 → 지우기 → 가져오기 왕복, 교체 전 개수 확인과 되돌리기, 시험 파일 거절. 1단계의 초록 '가져오기'는 파일 왕복만 증명하고 복원은 증명하지 않아요.

- **메타 태그는 안 넣어요.** [사실] WebKit은 '메타 또는 manifest display'라고 해요. 기기 측정은 iOS 18.6.2에 manifest display: standalone을 쓴 사례예요(메타 없이 동작했는지는 근거에 명시되지 않음). `black-translucent`는 글씨 사라짐 위험과 문서 충돌이 있어요. iOS 18에서 앱으로 안 열리면 그때 `apple-mobile-web-app-capable` 한 줄을 넣고 다시 추가해요.
- **서비스 워커 없음.**
- `id`만 절대 경로예요. 규격상 `./`는 도메인 루트가 되어 같은 계정의 다른 프로젝트와 겹칠 수 있어요.

**아이콘 제작:** `(작업 임시 폴더)\exp\icon.mjs`를 `scripts/make-icons.mjs`로 옮겨 한 번 돌리고 PNG를 커밋해요. 불투명(RGB) 정사각형으로 만들어져요. 색은 명시하고, 표식 크기는 1.0 이하로 둬요.

**[추론] 순서가 중요해요.** 설정이 아이콘을 추가하는 시점에 굳을 가능성이 높아요. 그래서 아이콘 승인 → 배포 → 홈 화면 추가 순서예요.

**감지** (`js/lib/device.js`, 값은 인자로)
```js
window.navigator.standalone === true || window.matchMedia('(display-mode: standalone)').matches
// openPlace(ua, maxTouchPoints, standalone) → 'app'|'ios-safari'|'kakao'|'other'
```
- `kakao`: `/KAKAOTALK/i` (흔한 방법이고 공식 문서는 못 찾음. 아이폰 실제 값은 비차단 캡처로 확인)

- 나머지는 `other`. 잘못 분류되면 없는 공유 버튼을 안내하게 되니 애매하면 `other`로 보내요.
- 기기는 안내 문구를 고를 때만 보고, 통과 판정은 standalone 값으로만 해요. `fullscreen`은 넣지 않아요. 자동 외부 이동은 하지 않아요.
- `deviceLabel`과 테스트 7개는 지우고 `openPlace` 테스트로 대체해요.

## L. 반영하지 않은 지적

- **2-11 디스크 프로필 + `mkdtemp`:** 브라우저 재실행을 `page.goto`로 바꿨으니(3-12) 고정 프로필 거짓 통과가 생기지 않아요.
- **2-8의 write newer 보호:** 1단계 값은 시험 기록뿐이고 형식이 안 올라가요. 2단계에서 다뤄요.
- **2-9의 강한 안(`reload`면 다시 열기로 안 셈):** 아이폰 실측 전에는 영영 통과 못 할 위험이 있어요. 값을 기록한 뒤 판단해요.
- **2-14의 쿠키 차단 경로 문구:** 그 설정이 홈 화면 앱의 저장을 막는지 모르는데 조치로 안내할 수 없어요.
- **1-14의 `file.type`으로 문구 고르기:** 공통 문장 하나로 해결되고 분기가 늘지 않아요.
- **1-4의 카톡 시험을 1부에 넣기:** 1부의 목적과 분리하려고 비차단으로 뒀어요(조건 ③이라 같은 날 권장).
- **1-7의 PC 확인을 2부 필수로:** 7개 합격과 별개인 J4 확인이라 승인 조건으로 두지 않아요.
- **3-9의 크기 상한 제거:** accept가 없어 큰 동영상을 고를 수 있어요. 수치만 20MB에서 1MB로 낮춰요.
- **3-11의 새로고침 확인 제거:** 사용자가 말한 항목이고 위쪽 버튼으로 추가 코드 없이 볼 수 있어요.
- **3-13의 저장 공간 분리를 폰 목록에서 완전히 빼기:** 읽기 하나로 관찰할 수 있으니 비차단으로 남겨요.
- **3-17의 UA 완전 제거:** 카톡 판별 확인에 필요해서 앱 밖에서만 원본을 보여 줘요.
